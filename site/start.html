Three ways in. Which one is yours depends on whether you are paying for work, doing the work, or checking somebody who already did.

01

I want to pay for work

Lock a reward on a piece of work. The money sits in a contract on GIWA and nobody can move it, Mergit included. When the pull request is merged and CI is green, the developer is paid.

You need a wallet and an amount.

Post a bounty 02 no wallet needed

I want to get paid

The escrow pays a wallet, so it has to know which one is yours. Put one line naming Mergit and your address in your GitHub profile README. That is the whole thing.

No wallet to connect. No gas. Nothing to sign.

See how, or register on-chain 03

I want to check someone

Every builder has a page: what they were paid, for which bounty, and who funded it. Read from the chain, with the proof re-checked against GitHub on every load.

You need their GitHub login.

Look up a builder

On registering

The README is enough. The chain is the upgrade.

One line in your profile README

  • Enough to be paid
  • Costs nothing, takes a minute
  • Nothing signed, no wallet connected

Registered on-chain

  • Everything the README gives you, and
  • The date is stamped and public
  • A builder page and a badge for your README
  • No repository owner can override it

One wallet holds one login, and the wallet that signs is the wallet that gets paid. To move a login to another wallet, the current one releases it first.

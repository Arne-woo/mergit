Three things live here. Which one you want depends on whether you are paying for work, doing the work, or checking somebody who did it.

01

I want to pay for work

Lock a reward on a piece of work. The money sits in a contract on GIWA and nobody can move it, Mergit included. When the pull request is merged and CI is green, the developer is paid. You get back a line to paste in the issue.

You need a wallet and the amount.

Post a bounty →

02

I want to get paid

The escrow pays a wallet, so it has to know which one is yours. Put one line naming Mergit and your address in your GitHub profile README, and that is enough to be paid.

Nothing else. No wallet to connect, no gas, no transaction.

Or register on-chain →

03

I want to check someone

Every builder has a page: what they were paid, which bounty, and who funded it. None of it was written by them or by us. It is read from the chain, and the proof is re-checked against GitHub every time the page loads.

You need their GitHub login.

Look up a builder →

About registering on-chain

Writing the line in your profile README is enough to be paid, and it costs nothing. Registering on-chain is the stronger version of the same thing: it stamps the date, gives you a builder page and a badge for your README, and it cannot be overridden by the owner of a repository you contribute to. It is an upgrade, not a toll.

One wallet holds one login, and the wallet that signs is the wallet that gets paid. If you want to move a login to another wallet, the current one releases it first.
